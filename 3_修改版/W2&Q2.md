**Weakness / Question 原文：** AVE-Agent combines multiple tools, retries, and strong external backends; the current ablation does not fully isolate the contribution of the proposed agent design. Since AVE-Agent is a complex multi-component system, more controlled ablations are needed to isolate the contributions of planning, refinement, external tools, and retry-based selection.

**中文翻译：** AVE-Agent 结合了多种工具、重试机制和强大的外部后端；当前的消融实验尚未充分隔离所提出的 Agent 设计本身的贡献。由于 AVE-Agent 是一个复杂的多组件系统，因此需要更加受控的消融实验，以分别隔离规划、优化、外部工具以及基于重试的结果选择所带来的贡献。

**Q2: 如何通过受控消融隔离 planning、prompt refinement、feedback 和 retry-selection 的贡献？**

**A2:** 感谢审稿人指出这一关键问题。为排除“更强 backbone、更多工具或更高测试时计算量”对结果的混杂影响，我们在同一评测子集上补充了受控消融。所有变体均使用 **相同的 Wan backbone、相同的外部工具集合和相同的输入数据**，仅改变规划、反馈利用、prompt refinement 和 retry-selection 策略，因此性能差异可以更直接地归因于 Agent 的编排设计。

这组对照的核心不是单独关闭某个模块，而是将三种竞争性解释分开：Naive Planner 检验结果是否只来自工具调用，Blind Retry 检验结果是否只来自额外采样，No Prompt Refinement 检验高层规划能否在缺少工具适配时直接转化为编辑性能。如此，表中每个差值都对应一个具体的替代解释。

相同 backbone 排除了模型容量差异，相同工具集合排除了工具覆盖差异，相近候选预算则用于区分反馈驱动的 refinement 与单纯增加 test-time sampling。

各设置定义如下：

* **Full AVE-Agent**：完整的结构化规划、工具级 prompt refinement、Evaluator 反馈、定向重试与 best-result selection。
* **Blind Retry**：保留相同的候选生成预算，但重试时不使用 Evaluator 反馈进行针对性修正。
* **No Prompt Refinement**：保留规划、评估和重试，但不将高层子任务转换为面向具体工具的精细化提示。
* **No Evaluation/Retry**：仅执行一次生成，不使用 Evaluator 反馈、重试或候选选择。
* **Naive Planner**：使用简单顺序规划替代结构化的跨模态任务分解与依赖建模。

结果给出了清晰且一致的组件贡献关系。

首先，**Full AVE-Agent 相比 Naive Planner 提升 24.5 分**，且 IF 提升最显著，说明主要收益来自结构化规划，而不是简单调用同一组工具。AVE-Agent 将自由形式指令分解为具有模态类型、依赖关系和评价标准的子任务，使复杂跨模态编辑能够按照正确顺序执行并显式处理音画依赖。

其次，Full 相比 Blind Retry 仍有明显优势，说明收益并非来自单纯增加生成次数。Blind Retry 拥有相近的 test-time sampling 预算，但由于无法利用 Evaluator 反馈定位错误并生成针对性修正，其表现明显低于完整系统。这表明关键因素是 **反馈驱动的定向 refinement**，而不是盲目扩充候选数量。

第三，Full 相比 No Prompt Refinement 的提升说明，高层编辑意图不能直接等价于具体工具的有效输入。将子任务转换为工具适配的 prompt、负面约束和执行规格，能够提升每一步编辑的准确性，并减少错误在后续步骤中的传播。

最后，Blind Retry 与 No Evaluation/Retry 的差距远小于 Full 与这两种设置的差距，进一步说明仅增加 retry 的收益有限；只有当重试由评估反馈引导，并结合 best-result selection 防止低质量候选覆盖已有结果时，额外计算才会稳定转化为性能提升。

因此，这组受控消融表明，AVE-Agent 的优势并非来自更强模型或更多工具，而是来自对相同 backbone 和工具集合的有效编排：**结构化规划负责建立正确的跨模态执行路径，工具级 prompt refinement 提高单步执行精度，Evaluator 反馈负责定位并修正错误，而 best-result selection 保证迭代不会引入性能回退。**

具体而言，Full vs. Naive Planner 隔离 planning 的贡献，Full vs. No Prompt Refinement 隔离工具适配的贡献，Full vs. Blind Retry 隔离反馈利用的贡献，而 Blind Retry vs. No Evaluation/Retry 则量化纯重试的收益。每个主要组件都有相应的受控对照。
