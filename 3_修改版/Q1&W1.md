### 共享源视频上的任务构成正交编辑分支

每条指令都从原始源视频独立开始，不会在另一条指令的编辑结果上继续修改，也不会使用其他任务的输出、标签或评测结果。对于同一源视频上的第 i 条任务，我们用以下干预签名描述其编辑目标：

**Tᵢ = (Oᵢ, Mᵢ, Eᵢ, τᵢ, Dᵢ)**

其中，Oᵢ 表示编辑算子，如增加、删除、替换或属性修改；Mᵢ 表示目标模态和编辑范围；Eᵢ 表示目标实体或事件；τᵢ 表示时间区间或空间区域；Dᵢ 表示所需的跨模态依赖。只要这些变量不同，任务就在编辑空间中具有不同的干预签名，而不是对同一编辑问题的重复采样。

具体而言，同源任务通过以下设计保持区分：

| 设计                           | 具体含义                                                                         |
| ------------------------------ | -------------------------------------------------------------------------------- |
| Independent editing branches   | 每条指令都直接作用于原始视频，而不是基于另一任务的编辑结果继续修改。             |
| Distinct edit operators        | 同源任务采用不同的增加、删除、替换、属性或时序操作。                             |
| Distinct target variables      | 不同任务涉及不同对象、事件、声源、人物属性或场景属性。                           |
| Distinct modality requirements | 不同任务分别作用于视频、音频、语音或联合音视频。                                 |
| Task-specific checklists       | 每条指令都有独立生成并经人工核验的 checklist，只判断该任务要求的修改和内容保持。 |
| No cross-task dependency       | 一条任务的输出、标签和评测结果不会被其他任务使用。                               |

例如，同一视频可以分别用于删除背景音乐、增加一个可见物体及其对应声音、替换说话人的身份和声音，以及同步修改动作速度与声音频率。这些任务虽然共享源内容，但编辑目标、操作类型和评测条件均不同，实际考察的是不同能力。

共享源视频固定了内容、场景复杂度和原始视频质量，因此也构成一种受控数据设计：不同编辑能力可以在相同输入条件下比较，减少源内容差异带来的干扰。共享的是受控的源内容，而不是编辑结果、标签或监督信号。它们是从同一受控源视频出发、具有不同干预签名的正交编辑分支。33 类 taxonomy 保证能力覆盖，13 个父类别和五次重复评测用于检验类别结论的稳定性；两者分别承担覆盖诊断和模型比较的作用。
